Release notes/v0.1.0-pilot.6

v0.1.0-pilot.617 November 2026Web, Android and backend

Background jobs you can follow, task states you can trust

Pilot.6 is about knowing where things stand. Side conversations became background jobs with clear states, tasks say what is really happening to them, and you can review a report by pointing at the part you mean.

How to updateDownloads on GitHub ↗

  • Main chat and background jobs

    Every job has a state and a place to answer its question. Switch between Main chat and jobs from the title.

  • Task states that follow the facts

    Needs you, working, waiting or paused, the same in the list, board and graph. No more tasks that claim to be in progress while nothing runs.

  • Reviews you can point at

    Select text or pick a block in a report, comment, and send one review. Agents revise from the version you read.

Conversations

Main chat and background jobs

When the coordinator starts a side conversation for a longer piece of work, that is now called a background job, and your ongoing conversation is the Main chat. Both names are used everywhere, so you always know where you are.

  • A state on every job Web · Android

    Needs you, Failed, Working, Paused, Finished or Stopped, in that order, so the jobs that wait on you come first. Finished and stopped jobs older than a day fold away under Finished.

  • Counts beside the title Web · Android

    The chat header shows how many jobs need you and how many are working. It no longer counts jobs that are merely unfinished.

  • Switch from the title Web · Android

    Press the conversation title to move between Main chat and any job. Each choice is a normal step in your history, so Back takes you where you were.

  • A job explains itself Web · Android

    A band under the job’s header says which project it belongs to, who started it and when, and where its report will go. Its open question sits right there with the answer form, next to a link to Main chat and a Stop button that asks before it stops.

  • What Main chat sees Web · Android

    A note by the composer reminds you that Main chat sees only the job’s report, not the messages you type inside the job.

Tasks

Task states that match what is happening

A task’s state now follows the facts: an open question, a failure, a running worker or a task it is waiting for. List, board, task sheet and graph all agree.

  • Needs you, working, waiting, paused Web · Android

    Tasks are grouped by what they need. A task that says in progress but has had nothing running for 15 minutes shows as paused, and its coordinator is nudged once to sort it out.

  • Blocked by another task

    A task can wait on other tasks. It shows which ones, and picks up again when they are done or dropped.

  • Closing a task that has open parts Web · Android

    Closing a parent while some of its parts are still open now asks what to do with them, instead of quietly leaving them behind.

  • Each state shown once Web · Android

    Rows and cards say the state in one coloured sentence instead of repeating it in a second line. A part of a task is no longer also listed as something found along the way.

  • Task numbers you can scan Web · Android

    Task IDs are small chips in lists, boards and the graph. Task mentions in a task’s own text are now live links with a preview, as they already were in chat, and pointing at one highlights the matching row or card.

  • Back goes back Web · Android

    Opening a task from another task shows a named Back control to where you came from. Leaving a conversation and returning restores the panel, the Tasks view and your scroll position.

Artifacts

Review a report by pointing at it

Reports and other artifacts are where you check the work. Giving feedback on them used to mean describing the spot in words.

  • Comment on the exact place Web · Android

    Select text, or pick a block in an HTML report, say what you want and add more comments as you read. Send them together as one review. It goes to the chat and to the task’s feedback, tied to the version you read. Unsent reviews stay on your device.

  • Agents work from the version you reviewed

    Agents can open any kept version of an artifact, edit a private copy and publish the result as the next version, so a revision starts from the real file.

  • HTML reports get the whole screen Web · Android

    An HTML report fills the viewer without a second title bar, with its actions in a ⋮ menu. On wide screens it opens as a large centred window; Escape closes it.

  • Large reports and links work Web · Android

    HTML reports up to 20 MiB render as pages instead of opening as source, which helps with image-heavy ones. Links inside a report now work.

Projects and agents

More say over how agents work

  • Skills per project Web · Android

    Project settings have a Skills page. Choose which of the discovered skills that project’s agents are offered, and see where each skill comes from. Skills you have not decided on stay available, as before.

  • See the worker models Web · Android

    The model picker in the composer now lists the project’s worker models with their provider and thinking level, and links to Worker settings.

  • Tell Kemiri your name Web · Android

    An optional Your name field in backend settings. Agents use it when they write about what you did or asked for. Leave it empty and nothing changes.

  • Workers stay on current code

    A worker in its own jj workspace is checked before each step and repaired once if its workspace went stale. It is told which revision it started from, and that ignored files such as installed dependencies are not copied in.

Look and feel

A candlenut, and calmer navigation

  • Meet the candlenut Web · Android

    Kemiri has a mascot. It is the app icon on web and Android, and in chat it breathes while an agent works and hops when the work finishes well. With reduced motion on, it stays still.

  • 12 or 24-hour time Web · Android

    Appearance has a time setting: Automatic, 24-hour or 12-hour. It applies to every clock in the app on that device.

  • One set of panel buttons Web · Android

    Tasks, artifacts and the other panels are chosen from the chat header only, and the open one is clearly marked.

  • Settings: Back, Up and Close Web · Android

    Back returns to the previous page, Up goes to the parent section and Close returns to where you opened settings from, at every screen width.

  • A new kemiri.dev

    The homepage now shows how Kemiri works with a small self-playing demo. These release notes are new too.

How to update

Update from pilot.5

Your projects, paired devices, credentials and settings stay where they are. Back up your Kemiri config and data folders first: an update can migrate data, and a rollback restores code, not data. This release converts your tasks once to the new states when it first starts. The app and the backend can be updated in either order; an older one keeps showing the earlier view until both are current.

  1. Update the backend from the app

    On an installed release, choose Update now beside the version in the navigation, or in Settings → About. Check the from → to versions and confirm. Kemiri waits for commands that are already running, restarts, and puts the previous version back by itself if the new one does not come up healthy.

  2. Or update from a terminal

    Stop Kemiri first: Ctrl-C in its terminal, or kemiri service remove if it runs as a user service. Then:

    Terminal
    kemiri update --version v0.1.0-pilot.6
kemiri start

    With a user service, run kemiri service install instead of kemiri start.

  3. Update the Android app

    Updating the backend does not update your phone. Get the signed APK from the v0.1.0-pilot.6 release page and install it over the app you have. Do not uninstall first.

Still on pilot.3 or earlier? Go through pilot.4 first, as the pilot.5 notes describe. New here? Start with the install steps.

Good to know

Limits and help

Still an early pilot. Linux is the tested host; macOS and Windows through WSL are experimental. The Android app needs Android 12 or newer and your backend reachable over HTTPS. There are no phone push notifications yet. Every paired device has full owner access, so keep the backend private.

Something off? Write to support@kemiri.dev with your version and what you saw. Never send credentials, pairing links or private conversations.
