Chats and usage

Keep the conversations apart and the work together

  • Coordinators for different areas Web · Android

    Give areas and jobs their own chats on the same board and switch without interrupting work. On web, start one from New coordinator in the sidebar and choose its model, thinking level and worker defaults in the composer. Android shows the model but does not have the per-coordinator pickers yet.

  • Choose how long chats are summarized

    Computer settings let you tune when the coordinator starts summarizing and when it waits for a summary.

  • Usage at a glance

    Limit gauges and charts are back in Glance. Usage on web and Android has tabs for all computers or one backend. Spend stays visible while refreshing.

  • Get ahead of fast subscription drain Web · Android

    Usage shows a forecast when a limit could run out before reset. Kemiri can warn or hold new requests without interrupting work in flight. A coordinator can investigate first. Pause or resume the subscription from Usage.

Notifications

Hear about the work without being interrupted by everything

  • Pop-ups, sounds and an inbox

    Get in-app alerts for replies, failures and work that needs attention. Choose which alerts pop up or make a sound. The web inbox keeps a history, even of alerts that never popped up.

  • Take a break from alerts Web · Android

    Use Do not disturb to silence pop-ups and sounds, or mute a project or computer on this device for an hour, eight hours or until unmuted.

Running apps

Try an agent’s app from another device

Open Running apps to see what’s listening, which links are published and the logs for apps Kemiri manages. The owner approves publishing for a project first. That approval also allows future apps in that project.

  • One-time tailnet setup

    Enable MagicDNS and HTTPS Certificates in Tailscale and start Kemiri at least once. Run kemiri tailscale enable --apps in a terminal as the account that runs Kemiri. This is separate from pairing the backend. kemiri tailscale status checks the Kemiri tailnet setup.

  • App links have no Kemiri sign-in

    Anyone the tailnet rules allow can open the link. Only publish apps safe for those people to see. Tailnet HTTPS puts the machine name in public certificate logs.

Artifacts and code

Find what changed and point to the part that needs work

  • A library across tasks

    Browse the Artifacts tab, pick an HTML report from its thumbnail when available, or compare saved versions. Pin an HTML artifact as a project panel. Leave comment pins in a report so the agent can see exactly where to revise it.

  • Code next to the conversation

    Browse project files or named checkouts. Review a committed change or work in progress and suggest an edit on a line. Direct file saves on web stay off unless enabled.

Tasks and tools

Get back to the work sooner

  • Review requests, not every part Web · Android

    Coordinators close checked parts, the request shows their progress, and go-live approval is asked once per request. The project Answers tab gathers quick replies, open questions and short errands in progress.

  • Classic task details

    Classic is the single task view on web and Android. Open a running worker’s transcript from the task’s Live section. Reconnecting skips old board updates, and saved files load when opened.

  • Settings sorted by what they change

    Project, computer and device settings are grouped separately on web and Android.

  • New downloads for workers

    Kemiri fetches a pinned agent-browser package from npm for browser proof and a pinned Antigravity archive for official-agent work, when needed.

How to update

Update from pilot.6

Your projects, paired devices, credentials and settings stay where they are. Back up your Kemiri config and data folders first: an update can migrate data, and a rollback restores code, not data. Update when idle, after backing up while stopped. This release uses pi 1.6.0. If you roll back to pilot.6, tasks, chats and finished work stay, but a turn running during the update cannot resume on pilot.6 because the saved format changed.

  1. Update the backend from the app

    On an installed release, choose Update now beside the version in the navigation, or in Settings → About. Check the from → to versions and confirm. Kemiri waits for commands that are already running, restarts, and puts the previous version back by itself if the new one does not come up healthy.

  2. Or update from a terminal

    Stop Kemiri first: Ctrl-C in its terminal, or kemiri service remove if it runs as a user service. Then:

    Terminal
    kemiri update --version v0.1.0-pilot.7
kemiri start

    With a user service, run kemiri service install instead of kemiri start.

  3. Update the Android app

    Updating the backend does not update your phone. Get the signed APK from the v0.1.0-pilot.7 release page and install it over the app you have. Do not uninstall first.

Still on pilot.3 or earlier? Go through pilot.4 first. On pilot.4 with Bun or source installs, Intel Macs or Linux musl, use the new checksum-verified installer with the same install directory: the old updater cannot read the new archive. See the full upgrade instructions. New here? Start with the install steps.

Good to know

Limits and help

Still an early pilot. Linux is the tested host; macOS and Windows through WSL are experimental. The Android app needs Android 12 or newer and your backend reachable over HTTPS. Android in-app alerts work while Kemiri is open; this pilot does not include phone push notifications. Every paired device has full owner access, so keep the backend private.

Official-agent subscriptions. Google does not support delegated work on consumer subscriptions and may suspend Antigravity or Gemini CLI access. A Gemini API key avoids that risk.

The macOS background service and phone pairing were covered by automated tests only, not by hand on a Mac or with a phone over a real network.

Something off? Write to support@kemiri.dev with your version and what you saw. Never send credentials, pairing links or private conversations.
