# Kemiri v0.1.0-pilot.6

17 November 2026. [What's new, with the update guide](https://kemiri.dev/releases/v0.1.0-pilot.6/).

An early, assisted pilot. A paired device has full backend access, including
files, shell and provider spending. Use your own accounts and repositories;
this is not a sandbox.

## What's new since pilot.5

- **Main chat and background jobs.** Side conversations have clearer names,
  attention-first states and separate needs-you/working counts. Switch from the
  conversation title; Back returns to the previous conversation. A job explains
  its origin, report destination and open question, with a guarded Stop action.
  Main chat sees the job's report, not your messages inside it.
- **Task states follow the facts.** Lists, boards, sheets and graphs agree on
  questions, failures, running work and blockers. In-progress tasks with no work
  for 15 minutes show as paused; their coordinator is nudged once per episode.
  Closing a parent with open parts asks whether to close or keep those parts as
  follow-ups. Task states are not repeated on rows and cards.
- **Review an artifact where you mean.** Select text or an HTML block, collect
  comments and send one version-addressed review to chat and, when task-linked,
  task feedback. Unsent reviews stay on your device. Agents can read retained
  artifact versions and revise a private copy into the next version.
- HTML reports render through 20 MiB and use the full phone viewer or a large
  centred desktop window, with actions in a menu. Report links work again.
- Task ID chips and live task references make tasks easier to scan and open.
  Conversation visits retain panels, Tasks mode and scroll; task drill-downs
  show a named Back control. Settings distinguish Back, Up and Close.
- Choose offered **skills per project**, inspect worker models in the composer
  picker, and optionally set **Your name** in backend settings for agent reports.
  Isolated workers detect stale jj workspaces and attempt one repair per check;
  their instructions explain their starting revision and dependency setup.
- A candlenut mascot, clearer selected panel buttons, device-local 12/24-hour
  clocks and a redesigned kemiri.dev with release notes.

## Before updating

Back up config and data while stopped; back up repositories separately. Projects,
paired devices, credentials and recorded installation paths stay in place. Do
not rename folders or uninstall Android. A rollback restores code, **not data**.

The backend repairs historical task combinations once **per project when its
board is initialized**, including archived tasks: incompatible parent links
become follow-up links, parents with started parts move from todo to in progress,
and contradictory blockers on review/waiting tasks become related links. It
keeps the existing stored status vocabulary; the new visible states are derived
from activity and questions, not a replacement database of statuses.

The new clients use capability-gated states and fall back to the old display on
older backends. Older clients can still read the retained statuses on a new
backend, but do not gain the new views or closing-parts prompt. New backend rules
can refuse old-client edits that now require that choice. Either update order
can connect, but update **both** before relying on the new task/review workflows.
Reload the web app after updating; update the Android APK separately.

## Update from pilot.5

On a supervised installed backend, **Update now** beside the navigation version
or in Settings → About downloads and verifies the selected release, waits for
running commands and restarts. Confirm the target is pilot.6. Cancel is available
before restart; forcing restart can kill commands. Failed health checks restore
the previous code automatically. This button does not update the Android app.

Or stop the foreground backend with Ctrl-C and run:

```sh
kemiri update --version v0.1.0-pilot.6
kemiri start
```

For a user service, use `kemiri service remove` before updating and
`kemiri service install` instead of `kemiri start`. Pilot.5's updater supports
both canonical executables and the source/private-Bun fallback.

## Update from pilot.4 or earlier

**Pilot.3 and earlier must first reach pilot.4**, while stopped:

```sh
aiki update --version v0.1.0-pilot.4
```

For a user service, stop it using the old command's `service remove` before the
bridge. Then continue below without starting the old backend.

**Pilot.4 standalone installs** (Linux glibc x64/ARM64 and macOS ARM64) can use:

```sh
kemiri update --version v0.1.0-pilot.6
kemiri start
```

**Pilot.4 Bun/source installs, Intel Macs and Linux musl (Alpine):** its embedded
updater requires an `aiki/` archive and cannot accept the new `kemiri/` archive.
Download, checksum-check and read pilot.6's installer instead:

```sh
curl -fL https://github.com/MitzaCoder/kemiri/releases/download/v0.1.0-pilot.6/install.sh -o kemiri-install.sh
curl -fL https://github.com/MitzaCoder/kemiri/releases/download/v0.1.0-pilot.6/install.sh.sha256 -o kemiri-install.sh.sha256
# Compare shasum -a 256 kemiri-install.sh with the downloaded checksum; read the script.
sh kemiri-install.sh --version v0.1.0-pilot.6 --runtime bun --no-service
kemiri start
```

Pass the **same absolute `--dir`** if originally installed with one; keep custom
installation/config path settings. Do not choose a new folder. A retained
pilot.4 `aiki` launcher can remain on this fallback path and select the new code;
use `kemiri` thereafter. For a user service, reinstall it instead of starting in
the foreground. Do not bypass checksum or archive-path validation.

Pilot.5 and later accept only `KEMIRI_*` process/build settings. Rename external
`AIKI_*` settings yourself before updating. Startup rewrites its own server.env
keys atomically, preserves the original as server.env.bak, and prefers existing
Kemiri keys. Existing data/config paths, service names and pairings stay intact.

## Android and fresh installs

Install the [signed APK](https://github.com/MitzaCoder/kemiri/releases/tag/v0.1.0-pilot.6)
over the existing app, without uninstalling. Public package stays
`io.github.mitzacoder.aiki`, with the permanent owner signing key. VersionName is
`0.1.0-pilot.6`, versionCode **1000006** (pilot.5: 1000005). Check the hash and
certificate in RELEASE-MANIFEST.json; private/debug builds may use another key.

Fresh installs: download and review [the release installer](https://github.com/MitzaCoder/kemiri/releases/download/v0.1.0-pilot.6/install.sh)
and its checksum, then run `sh install.sh --version v0.1.0-pilot.6`. The website
bootstrap can select this release with explicit `--version v0.1.0-pilot.6` after
publication; its default stays on the last verified public release until changed.

## Limits and help

Linux is the tested host path; macOS and Windows through WSL remain experimental.
macOS binaries are not signed/notarized. Native macOS service updates and
real-network Android pairing still require acceptance. Android needs Android
12+, a reachable HTTPS backend and an awake computer; the APK is not a tunnel.
There are no phone push notifications. Keep authentication on and the backend
private; every paired device has full owner access. Review MCP permissions.

Write to support@kemiri.dev with your version and redacted symptoms. Never send
credentials, pairing links or private conversations. Before publication, the
owner adds the exact commit, APK hash and certificate from RELEASE-MANIFEST.json
to the attached RELEASE-NOTES.md.
