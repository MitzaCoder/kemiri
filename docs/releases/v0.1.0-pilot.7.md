# Kemiri v0.1.0-pilot.7

24 November 2026. [What's new, with the update guide](https://kemiri.dev/releases/v0.1.0-pilot.7/).

An early, assisted pilot. A paired device has full backend access, including
files, shell and provider spending. Use your own accounts and repositories;
this is not a sandbox.

## What's new since pilot.6

- **Several coordinators in one project.** Give separate areas their own chats,
  tasks and background jobs without splitting the board. Switch instantly
  between recent chats while work continues. On web, start one from **New
  coordinator** in the sidebar and pick its model, thinking level and worker
  defaults in the composer. Android shows the model but does not offer the
  per-coordinator pickers yet. Tune long-chat summaries in Computer settings.
- **In-app alerts without the noise.** Get pop-ups for replies, work that needs
  attention and failures. Choose which alerts make a sound, snooze pop-ups and
  sounds with Do not disturb, or mute a project or computer on this device.
  The web inbox keeps alerts even when they don't pop up.
- **See and manage fast subscription drain.** Usage forecasts show when a limit
  could run out before it resets. Kemiri can warn or pause new requests on that
  subscription, leaving work in flight alone. A coordinator can investigate
  before asking what to do. Pause or resume from Usage on web or Android.
- **Usage at a glance.** Limit gauges and charts are back in Glance. Switch
  between all computers and individual backends with tabs in Usage. Spend
  stays visible while refreshing.
- **Open apps started by agents.** Running apps shows what is listening, which
  links are published and, for managed apps, the process log. Publish an HTTPS
  link for tailnet devices after the owner approves publishing in that project.
  That approval also allows future publishes there. Anyone the tailnet rules
  allow can open a published link without signing in to Kemiri.
- **Find and review work in Artifacts.** Browse a project's saved work across
  tasks, see cached HTML thumbnails, and pin an HTML artifact as a project
  panel. Open versions and compare them, or put a comment pin directly
  on the part of an HTML report that needs a change.
- **Read and review code without leaving the project.** Browse files and
  named checkouts, open committed or in-progress diffs, and suggest a line edit
  for an agent to review. Direct file edits are opt-in on web.
- **Less task noise.** Review requests, not every part: coordinators close
  checked parts, and each request shows their progress. Go-live approval is
  asked once per request. The project **Answers** tab gathers quick replies,
  open questions and short errands in progress. On web and Android, task
  details use Classic and **Live** links to running workers’ transcripts.
  Reconnecting loads less up front, and settings are grouped by project,
  computer and device.
- **Worker tools and accounts.** Kemiri downloads the pinned agent-browser
  package from npm for browser proof and the pinned Antigravity archive for
  official-agent work when needed. Google does not support delegated work on
  consumer subscriptions and may suspend Antigravity or Gemini CLI access. A
  Gemini API key avoids that risk.

## Before updating

Update when work is idle. Back up config and data while stopped and back up
repositories separately. Keep existing installation folders and pairings. This
release uses pi 1.6.0. Rolling back to pilot.6 keeps tasks, chats and finished
work, but cannot resume a turn that was running during the update: pi 1.6.0
saves running turns in a newer format. A rollback restores code, not data.

## Update from pilot.6

On a supervised installed backend, choose **Update now** beside the navigation
version or in Settings → About. Check the target version and let work finish
before restarting. Cancel is available before restart. Forcing restart can kill
commands; a failed health check restores the previous code automatically.

Or stop the foreground backend with Ctrl-C and run:

```sh
kemiri update --version v0.1.0-pilot.7
kemiri start
```

For a user service, use `kemiri service remove` before updating and
`kemiri service install` instead of `kemiri start`. Reload the web app after
updating. The backend update does not install the Android APK.

## Update from pilot.4 or earlier

**Pilot.3 and earlier must reach pilot.4 first**, while stopped:

```sh
aiki update --version v0.1.0-pilot.4
```

Pilot.4 standalone installations (Linux glibc x64/ARM64 and macOS ARM64) can
then use the `kemiri update` command above. **Pilot.4 Bun/source installs,
Intel Macs and Linux musl (Alpine)** need the new installer instead: pilot.4's
embedded updater expects an `aiki/` archive, not the new `kemiri/` archive.

```sh
curl -fL https://github.com/MitzaCoder/kemiri/releases/download/v0.1.0-pilot.7/install.sh -o kemiri-install.sh
curl -fL https://github.com/MitzaCoder/kemiri/releases/download/v0.1.0-pilot.7/install.sh.sha256 -o kemiri-install.sh.sha256
# Compare shasum -a 256 kemiri-install.sh with the downloaded checksum; read the script.
sh kemiri-install.sh --version v0.1.0-pilot.7 --runtime bun --no-service
kemiri start
```

Pass the same absolute `--dir` if originally installed with one. Keep existing
config and data paths and do not bypass checks. Use `kemiri` after activation,
even if the old launcher remains. Pilot.5 and later read only `KEMIRI_*`
process/build settings; rename external `AIKI_*` settings before updating.
Startup migrates keys in its own server.env and retains the original as a backup.
For a user service, remove it before upgrading and reinstall it after activation.

## Set up app links once

On the computer running Kemiri, sign in to Tailscale and enable MagicDNS and
HTTPS Certificates in the Tailscale admin console. Start Kemiri at least once,
then run `kemiri tailscale enable --apps` as the account that runs Kemiri, not
from an agent or with `sudo` in front of the command. It may ask for `sudo` to
reserve ports. Use **Tailscale HTTPS (reserved ports)** in **Settings → Advanced
→ Agent apps**. Approve publishing in **Running apps** only for projects whose
apps can be seen by anyone the tailnet rules allow. Kemiri sign-in does not
protect these links.

Tailnet HTTPS puts the machine name in public certificate logs. This app setup
is separate from pairing a device. Use `kemiri tailscale status` to check the
Kemiri tailnet setup. To pair Kemiri itself over HTTPS, use `kemiri tailscale
enable` and `kemiri pair --tailscale` with device sign-in required.

## Android and fresh installs

Install the [signed APK](https://github.com/MitzaCoder/kemiri/releases/tag/v0.1.0-pilot.7)
over the existing app, without uninstalling. The public package stays
`io.github.mitzacoder.aiki`, with the same signing key. VersionName is
`0.1.0-pilot.7`, versionCode **1000007** (pilot.6: 1000006). Check the hash and
certificate in RELEASE-MANIFEST.json; private/debug builds may use another key.

For a fresh install, download and review the [release installer](https://github.com/MitzaCoder/kemiri/releases/download/v0.1.0-pilot.7/install.sh)
and its checksum, then run `sh install.sh --version v0.1.0-pilot.7`. The website
bootstrap can select this release explicitly after publication. Its default is
only changed once the public assets verify.

## Limits and help

Linux is the tested host; macOS and Windows through WSL remain experimental.
macOS binaries are not signed or notarized. Android needs Android 12+, a
reachable HTTPS backend and an awake computer. The APK is not a tunnel.
Android in-app alerts work while Kemiri is open; this pilot does not include
phone push notifications. Keep authentication on and the backend private.
Review MCP permissions.

The macOS background service and phone pairing were covered by automated tests only, not by hand on a Mac or with a phone over a real network.

Write to support@kemiri.dev with your version and redacted symptoms. Never send
credentials, pairing links or private conversations. Before publication, the
owner adds the exact commit, APK hash and certificate from RELEASE-MANIFEST.json
to the attached RELEASE-NOTES.md.
