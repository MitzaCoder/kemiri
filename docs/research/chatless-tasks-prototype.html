Kemiri without the chat

A type box and a list of tasks. You say what you want. Work happens in the background. Whatever needs you rises to the top.

The short answer to “do we need the transcript at all?”

Not as the place you read. Tasks already do that better.

Not as the place you talk. The type box does that.

Yes as a hidden log, for the rare day you must see what an agent really did.

Yes as a short talk inside one task, when you want to think out loud. It folds into what was settled.

You sayA request, a question or feedback. One type box.
It landsA receipt shows where it went: a new task, two tasks, or a task you already have.
It fills inA first guess shows within a second. Then it keeps settling as work is done.
It risesWhen it needs you, it moves to the top with one clear ask.
You respondOne tap, or more words in the same type box. Then the loop runs again.

All data on this page is made up: a small stationery shop, used only as an example. The design is for any project.

The base that every direction shares

The loop, as one screen

This is the whole app: a list sorted by what needs you, and a type box. Open a task to see its output. There is no chat anywhere.

Try it

Each button sends that text through the type box. You can also type your own. Then let time pass, and open what rises.

Five bold directions

Five ways to push it further

Each one takes a different part of the idea to its end. They can be combined. Each has a prototype you can click.

1 · Diffusion: content that settles

A task has content within a second, as fast as a chat starts to answer. Then it is refined, pass after pass, until it is short, checked and final.

Step through one task

You asked: “Why did orders drop last week?” Watch the same task at five moments.

How the first draft appears

  • A fast, cheap model writes it from your words, the board and the project memory.
  • It uses no tools, so it takes about a second.
  • It says what it understood, gives a first guess, and lists what it will check.
  • For a change to code, the first pass is only the understanding and the plan. It never guesses a result.

What drives a pass

  • New evidence. A file was read, a check ran, a worker reported.
  • A stronger model. It rewrites what the fast one drafted.
  • A second look. Another agent checks each claim.
  • Quiet time. When nothing new comes, one pass cuts it to its shortest form.
  • You. Feedback, or opening the task, moves that part to the front.
  • No cause, no pass. Every pass names its cause.

Settling or final

  • Every line is marked: a guess, or checked.
  • The task shows a meter and the words “settling” or “settled”.
  • Unsettled content never sits under Needs you. Settling is what makes it rise.
  • Lines that changed since you last looked are marked.
  • A checked line that turns out wrong rises as a correction. It never changes silently.

Feedback in the middle

  • Your note becomes a pin that every later pass obeys.
  • The work is steered, not restarted. Checked lines the note does not touch stay.
  • “Good enough” stops the passes and the spending. Guesses stay marked as guesses.
  • “Keep this” locks a line against later rewrites.

Costs

  • The first pass is cheap: a small model and a small prompt.
  • The cost is in rewrites by strong models. A pass must patch the lines it touches, not rewrite the page.
  • A task gets a pass budget. Passes stop early when one changes almost nothing.
  • Nothing here is measured. A first build must count tokens for each pass.

Risks

  • You act on a wrong guess. The marks help, but a fast wrong answer still pulls.
  • Text moves while you read. Changes should land between reads, with marks.
  • The model believes its own guess. Later passes must get the evidence first, and the guess labelled as unchecked.
  • Polishing forever. The budget and the “changed almost nothing” rule end it.
  • Code cannot diffuse. The page about a change settles. The change itself is still built step by step.

Today's Kemiri already has the parts: a report rewritten in place, checks as data, a freshness mark when a report is stale. Diffusion adds the instant first pass, the mark on each line, and the rule that settling makes a task rise.

2 · Living page: the reply is a change

The agent never answers feedback with a message. It answers with a new version, and your note shows where it was worked in.

Try it

  1. Tap a part of the email, such as the headline.
  2. Pick a note, or type one. Tap nothing to note on the whole page.
  3. Let time pass. Draft 3 arrives with the change marked.
  4. Switch drafts, or show what changed.

Why it could win

  • Feedback points at a thing, so it cannot be misread.
  • Every note ends in a visible change, or it stays open.
  • The history is versions, not scroll.

Where it breaks

  • Outputs with nothing to point at, such as “make it faster”.
  • A note that needs an answer, not a change.
  • Each kind of output needs its own way to point.

3 · Promise first: assumptions, not questions

Before work starts, the task shows what you will get, how you will know it is done, and what the agent assumes. Review is checking the result against that promise.

Try it

  1. Read the promise. Change an assumption if it is wrong.
  2. Set how free the agent is.
  3. Start, then let time pass.
  4. Check each line against its evidence. Change an assumption after the fact to see what is redone.

Why it could win

  • Work does not stop for a question. It runs on a stated assumption.
  • A wrong direction shows in seconds, before it costs anything.
  • Trust is a setting you can see, for each task.

Where it breaks

  • A wrong assumption nobody read costs a redo.
  • Small requests do not deserve a contract.
  • Some things must be asked: money, deleting, going live.

4 · Clear the top: one thing at a time

The list is the map. The app is the top card. You answer, check or read one thing, and the next one slides in. When nothing is left, you are done.

Try it

Five different outputs wait. Act on each with a tap, type a note, or put it off. Then let time pass to see what comes back.

Why it could win

  • It fits a phone and a spare five minutes.
  • You never choose what to look at.
  • “Nothing needs you” is a real end.

Where it breaks

  • The order must be right, or you lose trust in it.
  • Big reviews do not fit a card.
  • You see less of the whole.

5 · Talk, then fold: a chat that does not stay

Some work is thinking out loud. A task can open a short talk. When you end it, only what was settled stays on the task.

Try it

  1. Open the talk.
  2. Send the offered lines, one at a time.
  3. End the talk at any point and see what stays.

Why it could win

  • It admits that fast back and forth is real work.
  • The talk has one subject and an end.
  • Nobody has to read it again. The task holds the result.

Where it breaks

  • It is a chat. If every task grows one, nothing changed.
  • The fold can drop something that mattered.
  • A talk across two tasks has no home.
Rich content

Any output, the same five moves

Outputs differ wildly. The process can stay the same if every kind of output answers the same five questions. Pick a kind.

A new kind of output is then a small contract, not a new screen. The frame around it never changes: state, what needs you, the output, the record.

BreaksTwenty quick questions a day make twenty tasks.

BreaksWith diffusion, text changes after you read it.

CoverMarks for what changed. Corrections to checked lines rise on their own.

Still openIt asks more attention than text that is simply final.

Agents write for a chat Medium

BreaksModels answer in conversation by default. Earlier research here found steps and answers left only in the chat.

CoverOne agent per task: its reply is the task's content, so nothing can leak elsewhere.

Breaks“Do it like the other one” needs something that knows both.

Recommendation

Build the loop, let content diffuse, answer with changes

The loop is the product: the type box, the receipt, five asks, and a list sorted by what needs you.

Diffusion is how every task fills in. It replaces the one thing a chat does best: answering at once.

The living page is how every output is improved. A note ends in a version, never in a message.

The promise is not a gate. It is simply what the first diffusion pass writes.

Talk stays as a mode inside a task. Clear the top can become the phone's home screen later.

A path, in five steps

  1. A week with the chat off. On today's app, a switch hides the transcript. Each time you open it anyway, one tap says why. That list is the real gap.
  2. The loop. On the next-big branch, web only, on today's board. The hidden coordinator still runs underneath.
  3. Diffusion for questions and findings. A fast first pass, marks on each line, and the rule that settling makes a task rise. Count the tokens of each pass.
  4. The living page. Notes pinned to parts of an output. The review comments on HTML pages that exist today are the start.
  5. One agent per task. Then test whether a fresh agent can go on from a task page alone.
