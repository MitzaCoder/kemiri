How to update

Update from {{PREVIOUS_SHORT}}

Your projects, paired devices, credentials and settings stay where they are. Back up your Kemiri config and data folders first: an update can migrate data, and a rollback restores code, not data. TODO: anything special about this update, or delete this sentence.

  1. Update the backend from the app

    On an installed release, choose Update now beside the version in the navigation, or in Settings → About. Check the from → to versions and confirm. Kemiri waits for commands that are already running, restarts, and puts the previous version back by itself if the new one does not come up healthy.

  2. Or update from a terminal

    Stop Kemiri first: Ctrl-C in its terminal, or kemiri service remove if it runs as a user service. Then:

    Terminal
    kemiri update --version {{TAG}}
kemiri start

    With a user service, run kemiri service install instead of kemiri start.

  3. Update the Android app

    Updating the backend does not update your phone. Get the signed APK from the {{TAG}} release page and install it over the app you have. Do not uninstall first.

Still on pilot.3 or earlier? Go through pilot.4 first, as the pilot.5 notes describe. New here? Start with the install steps.

Good to know

Limits and help

Still an early pilot. Linux is the tested host; macOS and Windows through WSL are experimental. The Android app needs Android 12 or newer and your backend reachable over HTTPS. There are no phone push notifications yet. Every paired device has full owner access, so keep the backend private.

Something off? Write to support@kemiri.dev with your version and what you saw. Never send credentials, pairing links or private conversations.
